# 数据出境合规 · 自检问卷（E2 · 境外机房的必办项）

> 生成：2026-09-19 ｜ 依据：`external-blockers.md` §2.1
> 背景：E2 机房选**中国境外** ⇒ **免 ICP 备案**，但急救侠处理**用户个人信息**（姓名、手机号、位置、救援记录）
> 属《个人信息保护法》下的**个人信息出境**，仍需合规评估。本问卷供**你 / 法务**照单作答，
> 结论决定部署架构（是否境内数据中转、脱敏/加密实现）。工程侧据此再立 F 项。
> ⚠️ 本文件是**自评清单**，非法律意见；最终路径以法务结论为准。

---

## 0. 为什么必须做（一句话）
境外机房 ≠ 免合规。个人信息出境走「标准合同备案 / 安全评估 / 认证」三选一，阈值看**数据类型 + 量级**。

---

## 1. 自检问题（逐条答，法务可据此判定路径）

| # | 问题 | 你/法务填 |
|---|------|----------|
| Q1 | **境外落地地区**？（香港 / 新加坡 / 美西 / 其他） | |
| Q2 | **出境数据类型与字段清单**？（姓名、手机号、位置、救援记录、是否含健康/医疗相关） | |
| Q3 | **预计出境数据量级**？（活跃用户数 / 日出境条数）⇒ 决定阈值档位 | |
| Q4 | **是否可境内留存、仅境外缓存/计算**？（最小化出境原则） | |
| Q5 | **字段级脱敏/加密方案**？（手机号掩码、位置粗化至城市级、传输 TLS、静态加密） | |
| Q6 | **境外接收方**是谁？角色？是否签**标准合同**？ | |
| Q7 | **用户告知与同意机制**？（隐私政策、单独同意、撤回入口） | |
| Q8 | **数据留存期限 + 删除/导出机制**？（满足"最短必要"） | |

---

## 2. 路径判定（法务结论后回填）

| 情形 | 路径 | 动作 |
|------|------|------|
| 出境达**安全评估**阈值（重要数据 / 大量个人信息） | **通过安全评估**（国家网信部门） | 走评估申报 |
| 一般个人信息、签标准合同 | **标准合同 + 备案**（网信部门） | 拟合同、备案 |
| 符合认证条件 | **个人信息保护认证** | 申请认证 |
| 出境合规成本过高 | **回退「中国大陆 + ICP 备案」** | 改 E2 步骤 1 另一分支 |

---

## 3. 工程侧待办（待 Q1–Q8 + 法务结论后立 F 项）

- [ ] 确认是否需**境内数据中转**（境外只拿脱敏/聚合结果）
- [ ] 实现 **字段级脱敏**（手机号掩码、位置粗化）
- [ ] 传输/静态**加密**方案（已在 DEPLOY.md 默认 TLS；静态加密按结论补）
- [ ] 隐私政策 + **单独同意**埋点（前端 i18n 已就绪，文案待补）
- [ ] 留存期限 + 删除接口（现有 `service:purge` / `sos:purge` 可作基础）

## 4. 与 E1 的衔接
E1 短信回调用例 `https://<域名>/api/public/aliyun-sms-report` 依赖 E2 已可达域名；
若 E2 最终走「境内数据中转」，回调域名仍用**境内接入层**，与境外机房解耦。
