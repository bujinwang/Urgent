## 0. 一句话结论

**有。** 优先级排序：

1. **微信小程序原生 `<map>` 组件**（最优）：底层即腾讯地图，**免 Key、免商业授权、零成本、合规**；`manifest.json` 里 `mp-weixin` 已配置、位置权限已声明 ⇒ 几乎零新增外部依赖。
2. **腾讯地图 JS GL / 天地图**（H5 端要真地图时）：两者都有面向**非商业 / 公益 / 个人**的免费额度；天地图是官方平台，基础服务免费、政务公益认可度最高。
3. **保留现有降级草图 / 列表**（PRD D3）：本来就是零成本、零 Key、零合规风险，且已合并 + 测试。

## 1. 合规硬约束（不可协商）

| 允许 | 禁止 |
|------|------|
| 腾讯地图、高德地图、百度地图、**天地图**（国家地理信息公共服务平台） | Google Maps、Apple Maps、Bing 海外版、Mapbox、**OpenStreetMap 直连海外瓦片**、Leaflet+OSM、任何无测绘资质的第三方瓦片 |

- 理由：地图数据须有**测绘资质 + 审图号**，领土表达（国界、台湾、南海诸岛）须符合国家标准；开源方案只解决**代码授权**，底图数据来源合规、审图责任仍需自行承担，对外商用并不省钱。
- 坐标：境内必须用 **GCJ-02**（腾讯 / 高德）；天地图为 CGCS2000（≈WGS-84）⇒ 见 §4 坐标系坑。
- 密钥纪律：前端 JS 里明文 Key 可被嗅探。个人用配 Referer 域名白名单；商用须**后端代理**鉴权。**仓库里绝不出现真实 Key**（PRD D4 已遵守）。

## 2. 「免费」的真相：免费 ≠ 可商用

各家 JS API 都有免费额度，但**免费只覆盖非商业用途**；商业授权是「按主体 + 按年」签的准入费，与调用量无关。

| 平台 | 免费 / 非商业额度（量级，以控制台为准） | 商用授权 | 备注 |
|------|------------------------------------------|----------|------|
| **高德** | 个人认证有月额度；企业认证「非商业目的」有更大额度（限 1 年） | **约 5 万元/年**（基础版） | 现用方案；JS API 地图展示按瓦片加载计次 |
| **腾讯** | **非商业使用免费**；个人未认证 ~1 万次/日、认证后 ~5 万次/日 | **约 5 万元/年** | 官方明确把「**非盈利的公益项目**」列入免费范畴；企业及非公益机构须授权 |
| **百度** | 个人 / 基础版日额度较低（数千次/日量级） | 约 5 万元/年 | 另有低价「企业认证版」，但资质效力在招投标 / 上架场景存疑 |
| **天地图** | **基础服务免费**；个人实名后可申请 Key（浏览器端 `tk`），日配额约万次/服务量级 | **商用需单独申请许可**（条款可沟通） | 官方背景、带审图号、政务 / 公益项目合规性最好交代 |

> 💡 **对急救侠最关键的一点**：这是**公益急救项目**，不是电商 / 出行 / SaaS。腾讯把「非盈利的公益项目」明确列为免费使用场景，天地图对政务公益类项目认可度最高 ⇒ **很可能根本不需要买 5 万/年的商用授权**。但「公益」如何认定、是否需向平台报备，**以厂商最终答复为准**，不要自行假设。
> ⚠️ 边界模糊处：项目若含广告 / 赞助 / 付费功能，可能被判「间接获利」而触发授权义务。

## 3. 为什么「微信小程序原生 `<map>`」是最优解

**工程事实（已核实）**：
- `急救侠-uniapp/src/manifest.json` 已配 `mp-weixin`（`appid` 待填）、`permission.scope.userLocation`、`requiredPrivateInfos: [getLocation, chooseLocation]`、`app-plus.modules.Maps` ⇒ **小程序与 App 都是既定交付目标**。
- 但当前 `pages/aed/MapCanvas.vue:46-55` 是 **DOM + 动态 `<script>` 注入 `webapi.amap.com`**，用 `new AMap.Map` / `new AMap.Marker`。小程序环境**没有 `document`、不能注入 script、`<view>` 不是 `HTMLElement`** ⇒ 这条路径**在小程序端本来就跑不通**，小程序用户现在 100% 走降级草图。
- ⇒ 换原生 `<map>` 不是「增加一条新通道」，而是**把本来就浪费的小程序通道用起来**，且不引入任何新 Key / 新采购 / 新合规主体。

**微信原生 `<map>` 的性质**：
- 底层为腾讯地图（合规白名单内），由微信提供，**开发者无需单独申请腾讯位置服务 Key**，也无需商业授权。
- 支持 `latitude` / `longitude` / `markers` / `include-points` / `polyline` 等，覆盖 AED 打点需求；`getLocation` 等敏感接口需在微信公众平台按类目申请权限（展示与 markers 本身不需要）。
- 免费、境内可用、无域名白名单 / 备案耦合。

**与 E2 的关系**：E2 定的是**境外机房**（免 ICP 备案）。地图 SDK / 瓦片是**客户端**从厂商 CDN 拉取，与服务器机房位置无关 ⇒ E2 决策**不阻塞**本方案。但若后续 H5 方案要把 Key 的 Referer 白名单绑到境外域名，需确认厂商对域名备案的要求（与 E1 的资质主体问题可能是同一类坑）。

## 4. ⚠️ 坐标系坑（换厂商前必须查）

- 腾讯 / 高德：**GCJ-02**（火星坐标）。百度：BD-09。天地图：CGCS2000 ≈ WGS-84。
- 后端 `aed_devices.lat / lng`（`db.ts:215-242`）当前按**高德 GCJ-02** 口径写入。
- ⇒ 换**腾讯 / 微信原生 `<map>`**：同为 GCJ-02，**坐标零改动**，最省事（另一条支持这个选择的理由）。
- ⇒ 换**天地图**：不经坐标转换会产生数百米级整体偏移，**必须加一层 WGS-84↔GCJ-02 转换**，且要回归验证所有 AED 点位。
- ⇒ 换**百度**：需 GCJ-02→BD-09 转换。

## 5. 切换成本（复用 PRD D2 薄适配层）

`src/utils/map/adapter.ts` 的设计就是「厂商可换只改本文件」，页面只依赖自有 `MapMarker` 模型。但实际改动面比注释略大：

| 文件 | 改动 |
|------|------|
| `src/utils/map/adapter.ts` | `MAP_KEY_ENV`（`VITE_AMAP_KEY`）→ 新环境变量 / 或改为「无需 Key」；`loadAmapSdk()` → 对应 SDK loader 或改由条件编译绕过 |
| `src/pages/aed/MapCanvas.vue` | `:46-55` 的 `new AMap.Map` / `new AMap.Marker` 是**硬编码厂商全局 API**，须改为 `TMap.Map` / `TMap.MultiMarker`，或小程序端用 `#ifdef MP-WEIXIN` 分支改为 `<map :markers>` 模板 |
| `src/pages/aed/index.vue` | `showRealMap = ref(isMapEnabled())` 的启用判据要按平台分流（小程序恒 true，H5 看 Key） |
| 测试 | `aed-map-canvas.test.ts` / `map-status.test.ts` 的「无 Key 必 fallback」断言需按平台调整；新增小程序 markers 映射测试 |

> 建议顺手把 `new AMap.Map/Marker` 也收进 adapter（暴露一个 `createMap(el, center, markers)`），才算真正做到「只改一个文件」。
